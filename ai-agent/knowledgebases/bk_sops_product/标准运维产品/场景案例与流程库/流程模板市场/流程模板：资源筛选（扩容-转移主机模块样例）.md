## 八大通用流程模式

### 1. 告警屏蔽模式
几乎所有发布/重启/变更流程都应遵循此模式（全局 1,845 个流程使用告警屏蔽）：
```
屏蔽告警（monitor_alarm_shield / tnm2_alarm_shield）
    ↓
执行操作（发布/重启/变更）
    ↓
取消告警屏蔽（monitor_alarm_shield_disable / tnm2_alarm_unshield）
```

### 2. 人工检查点模式
关键操作前的人工确认（全局 9,043 个节点使用 pause_node）：
```
bk_notify（展示操作信息/参数）→ pause_node（等待人工确认）→ 执行操作
```

### 3. 并行 + 汇聚模式
可并行的操作同时执行，提升效率：
```
ParallelGateway
├── 分支 A（如 QQ 区更新）
├── 分支 B（如 WX 区更新）
└── 分支 C（如 Guest 区更新）
ConvergeGateway → 后续操作
```

### 4. TCM 部署标准序列
TCM 配置的标准部署顺序（全局 6,482 个 TCM 任务节点）：
```
checkconf → disable autoload → install version → enable autoload
```

### 5. 分批灰度模式
降低发布风险的分批策略：
```
第一台 → 验证（pause_node）→ 第 2 批 → 等待 → 第 3 批 → ... → 全量
```
多渠道场景下必须先发布手Q（SQ）渠道验证无问题后，再发布微信（WX）渠道。

### 6. 滚动重启模式（无损）
结合 CLB 的无损重启：
```
A 组: CLB 摘流量 → stop → start → 健康检查 → CLB 恢复权重
B 组: CLB 摘流量 → stop → start → 健康检查 → CLB 恢复权重
```

### 7. 通知闭环模式
关键操作前后的通知：
```
开始通知（bk_notify / wechat_work / BKChat）
    ↓
执行操作
    ↓
完成/失败通知
```

### 8. 备份-操作-验证模式
数据变更的标准流程：
```
备份（全量/增量）→ 执行变更 → 验证数据一致性 → （失败则回滚）
```

## 流程优化检查清单（通用）

在检查任何流程时，建议逐项核对以下要点：

### 高优先级
1. **告警管理**: 变更操作是否有告警屏蔽/取消屏蔽？（屏蔽组件是否配对？）
2. **人工确认**: 高危操作前是否有 pause_node？
3. **CLB 管理**: 涉及进程重启时是否有 CLB 权重管理（摘流量 → 重启 → 健康检查 → 恢复权重）？CLB 操作前是否查询并备份当前规则，操作后是否对比验证？
4. **数据备份**: 涉及数据变更时是否有备份步骤？
5. **灰度策略**: 全量发布前是否有灰度验证环节？
6. **健康检查**: 启动/重启后是否有健康检查？

### 中优先级
7. **TCM 配置**: 涉及 TCM 时是否遵循标准序列？
8. **通知机制**: 关键阶段是否有通知？
9. **回滚方案**: 是否有失败回滚路径？
10. **CMDB 同步**: 扩缩容后是否同步 CMDB？
11. **版本记录**: 是否有版本信息记录/SVN 更新？

### 低优先级
12. **并行优化**: 独立操作是否使用并行网关？
13. **定时等待**: 停服前是否有公告等待时间？
14. **审批集成**: 高危变更是否有审批流程？
15. **子流程封装**: 重复逻辑是否封装为子流程（SubProcess）？

## 成熟度等级 — 场景适用性映射

判定成熟度等级时，以下表格标注各场景中**不适用**的检查项。不适用项在判定时自动视为"通过"，不影响等级。**未列出的场景表示所有检查项均适用。**

- **L2-屏蔽**: 告警屏蔽/取消配对

- **L3-凭证**: 无明文密码/密钥
- **L4-灰度**: 灰度验证环节
- **L4-备份**: 变更前备份
- **L4-回滚**: 失败回滚路径
- **L4-CLB**: CLB 无损发布
- **L5-审批**: 审批流程集成
- **L5-复用**: 子流程复用
- **L5-并行**: 并行网关优化
