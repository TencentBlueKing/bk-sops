# 休闲棋牌

> 休闲棋牌包括斗地主、麻将等轻度对战游戏。运维流程特点是**流程极度精简化（中位=1 节点）**、蓝盾流水线驱动为主（devops-pl-plugin 93 次）、七层权重管理、故障自愈链路完善。
>
> **302** 条流程 | **4** 个业务 | 平均节点数 2.0 | 中位节点数 1

## 关键检查点（Review 要点）

1. **蓝盾流水线触发正确性**：devops-pl-plugin（0.31/流程）是核心，需确认流水线参数传递、触发条件和回调处理
2. **七层权重灰度策略**：hcm-weight-seven（35 次）用于灰度发布，需确认灰度比例（权重）设置和灰度验证步骤
3. **故障自愈链路完整性**：部分棋牌业务有完整的故障自愈流程（电话审批→uWork重启→故障处理→重启），需确认自愈触发条件和多重重启的安全性
4. **ITSM 工单审批合规**：bksops-itsm（15 次）联动，需确认工单审批流程的合规性
5. **初始化部署标准化**：初始化流程（authagent/cmlb/lib 部署）需确认分发→部署→配置检查的完整链路
6. **单节点流程的异常处理**：中位=1 节点，大量单步流程需确认是否有足够的异常处理（超时、重试、通知）

## 代表性流程

**流程 1**：故障自愈（5 节点）
```
电话通知审批 → uWork重启(失败后自动派现场) → QQgame大厅和微信环境转发层切换故障处理 → uWork重启 → uWork重启
```
> 特点：多重 uWork 重启+电话审批的故障自愈链路

**流程 2**：初始化部署（7 节点）
```
分发lib文件 → 分发cmlb_client → 分发AuthAgent → 部署lib → 部署cmlb_client → 部署启动authagent → 配置检查
```
> 特点：标准的初始化分发+部署+检查流程

**流程 3**：调用 Agent 通用流程（5 节点）
```
调用BKAI Agent → [重试]调用BKAI Agent → 通知开发者 → 通知开发者 → 正式推送
```
> 特点：AI Agent 集成的标准模式，含重试机制
