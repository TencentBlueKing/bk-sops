# FPS 射击类

> FPS 射击类游戏以实时对战为核心，服务器架构多为 Match-Based（匹配制），强调低延迟和高可用。运维流程特点是多环境/多平台分支管理复杂、预发布验证严格、TCM 配置管理深度集成。
>
> **3,151** 条流程 | **28** 个业务 | 平均节点数 6.4 | 中位节点数 3

## 关键检查点（Review 要点）

1. **预发布验证闭环**：FPS 预发布流程占比最高（10.9%），Review 时必须检查预发布环境与正式环境的配置一致性
2. **多环境分支完整性**：排他网关使用率 19.1%，检查每个条件分支是否都有对应的处理逻辑（如 iOS/Android/PC 各平台）
3. **TCM 配置变更原子性**：TCM 使用极高频，需检查 TCM 变更是否有回滚机制
4. **混沌工程集成**：chaos-atom 插件在 FPS 中特有高频使用，需验证故障注入和恢复流程的完整性
5. **xxx_cls 中转服操作**：FPS 系列流程中的 xxx_cls 操作必须遵循加锁→操作→解锁模式
6. **在线数据巡检**：FPS 类普遍有在线数据分析巡检流程，需检查数据采集→分析→告警的完整链路
7. **蓝盾流水线联动**：devops-pl-plugin 使用频繁（152 次），需检查流水线触发与 SoPS 流程的状态同步

## 代表性流程

**流程 1**：在线智能分析巡检（5 节点）
```
开始 → 最近2小时在线数据 → 昨天2小时在线数据 → 上周2小时在线数据 → BkChat通知 → 在线分析 → 结束
```
> 特点：AI 分析 + BKChat 通知的轻量巡检模式

**流程 2**：版本发布（134 节点，参考场景文档）
```
开始 → DB备份提单 → 版本文件准备 → xxx_cls 白名单 → 中转服维护 → [并行] → TNM2告警屏蔽 → 关闭充值接口 → xxx_cls加锁 → [汇聚] → xxx_cls发布 → 解锁 → 停服 → 清共享内存 → 关闭进程 → ... → 结束
```
> 特点：xxx_cls 中转服操作完整闭环、告警屏蔽、多阶段人工确认

**流程 3**：通用业务亲和性 Agent 调用（5 节点）
```
开始 → 调用 BKAI Agent → 通知开发者 → 调用 BKAI Agent → 正式推送 → 通知开发者 → 结束
```
> 特点：AI Agent 运维的新模式，该领域先行者
