> 开放世界生存类游戏以大地图探索和生存玩法为核心，代表了新一代游戏架构趋势。运维流程特点是 BKChat 使用密度全类型最高、GCloud 全链路发布管理、BCS Ingress 管理是独特需求、条件并行率全 MMORPG 子类最高（6.2%）。

## 关键检查点（Review 要点）

1. **GCloud 全链路发布一致性**：预发布→发布→产品发布三步需确保多渠道（安卓/iOS/鸿蒙）的版本一致性
2. **BCS Ingress 配置正确性**：bcs-ingress-ck（53 次）检查 Ingress 配置，需确认发布后的 Ingress 规则更新
3. **BKChat 通知覆盖**：BKChat 密度全类型最高（0.41/流程），需确认关键步骤的通知覆盖，但也要避免通知过多造成噪音
4. **研发自助操作边界**：部分业务有大量"研发自助"流程，需确认自助操作的权限和审批边界
5. **条件并行分支完整性**：条件并行 6.2%（最高），需检查各条件分支（如安卓/iOS 条件）是否都有完整处理
6. **角色数据导入导出安全性**：部分业务的角色导出/导入流程需确认 COS 存储的权限和数据清理

## 代表性流程

**流程 1**：GCloud 发布（10 节点）
```
参数解析 → 蓝盾执行流水线资源发布 → BKChat通知运维 → bkchat通知开发商 → 添加dolphin版本号(安卓) → 添加dolphin版本号(iOS) → 发布单个渠道 → BKChat通知运维 → bkchat通知开发商 → bkchat通知开发商
```
> 特点：蓝盾+GCloud+BKChat 的三方联动发布

**流程 2**：研发自助角色导出导入（8 节点）
```
角色导出 → 获取任务日志 → 快速分发文件 → 上传COS → 人工确认 → 消息展示 → 角色导入 → bkchat通知
```
> 特点：研发自助的数据导出导入流程

**流程 3**：SRE 稳定性巡检（8 节点）
```
SRE-稳定性巡检 → sa服务器类型检查 → SRE-CC主机计费模式切换 → SRE-检查云石FTP → 消息展示×4
```
> 特点：标准化的 SRE 巡检模板，多个开放世界业务共用同一模式
