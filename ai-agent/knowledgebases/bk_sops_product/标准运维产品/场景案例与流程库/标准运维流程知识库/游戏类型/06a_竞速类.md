> 竞速类以 QQ 飞车系列为代表，以实时对战竞速为核心玩法。运维流程特点是 TCM 配置管理密度高（0.406/流程，每个 Roomsvr 都需 TCM 操作）、**灰度发布最精细（分批 × 分区 × 分渠道 QQ/WX）**、CLB 权重管理+AI 巡检双轨保障。
>

## 关键检查点（Review 要点）

1. **分批灰度完整性**：灰度（19.4%）是核心模式。标准链路：获取RS IP→CLB 权重→第1批（QQ+WX 并行）→暂停确认→第2批→暂停→第3批→全量。需确认每批都有确认节点
2. **TCM 配置四步联动**：refreshbuscfg → createcfg → pushcfg → reload 四步缺一不可
3. **CLB 权重变更闭环**：clb-mdweight 修改后需确认恢复操作，避免 RS 永久摘除
4. **TNM2 屏蔽/解除配对**：33 次屏蔽 vs 22 次解除，需检查是否有未解除的屏蔽
5. **刷档操作安全性**：刷档（4.9%）涉及数据覆写，需确认备份和灰度验证
6. **AI 巡检覆盖**：SPEED 飞车的 AI 巡检体系需确认巡检结果的通知和异常处理

## 代表性流程

**流程 1**：3 批 Roomsvr 灰度发布（33 节点）
```
暂停 → [并行] QQ区 roomsvr灰度子流程 + WX区 roomsvr灰度子流程 → 暂停15分钟 → [并行] 第2批 QQ+WX → 获取第3批RS IP → 发送分批信息 → [并行] 第3批 QQ+WX → 快速执行脚本 → 消息展示
```
> 特点：3 批 × QQ/WX 双区并行 = 6 组灰度操作，每批间暂停确认

**流程 2**：预发布更新（17 节点）
```
refreshbuscfg → createcfg → pushcfg → listproc → reload → 暂停 → 停服踢人 → stop → reload → start → refreshbuscfg → 重启tcmcenter → 暂停 → ...
```
> 特点：TCM 四步配置操作的完整链路

**流程 3**：AI 日常负载巡检（11 节点）
```
[并行] 电信区巡检 + 电信2区巡检 + 网通区巡检 + cvm总览 + cvm亲和性巡检 → Markdown转化器×3 → 发送邮件×2 → 发送通知
```
> 特点：多区域并行巡检 + AI 分析 + 邮件报告的完整巡检链路
