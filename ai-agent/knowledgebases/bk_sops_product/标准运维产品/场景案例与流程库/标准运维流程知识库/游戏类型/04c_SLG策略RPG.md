# SLG 策略 RPG

> SLG 策略 RPG 包括三国/战争策略类游戏，以区服运营和全球同服为特征。运维流程特点是 TCM 密度全子类最高（1.25/流程）、区服运营状态管理（开服/维护/白名单）为核心操作、Tendis 缓存管理是独特需求、并行率最低（6.6%）体现串行化的运营操作特征。
>
> **1,304** 条流程 | **8** 个业务 | 平均节点数 7.2 | 中位节点数 3

## 关键检查点（Review 要点）

1. **区服状态管理闭环**：SLG 的区服状态（正常→维护→合并/关闭）需要 cc_batch_update_set + webplat_game_area_operate 联动，确保 CMDB 和游戏平台状态一致
2. **TCM 变更频率控制**：TCM 密度 1.25/流程全类型最高，需确认高频变更的灰度验证策略
3. **Tendis 缓存一致性**：bkdbm-tendisclr 使用 13 次，清缓存操作需确认时机（如合服后、开区前）
4. **白名单管理合规性**：白名单占比 1.4%（SLG 独有高频），需确认白名单的添加/移除有审批流程
5. **开服/开区初始化完整性**：开服（4.5%）+开区（3.4%）合计 7.9%，需确保 DB 初始化→配置生成→区服上线→状态更新的完整链路
6. **串行操作顺序正确性**：并行率最低（6.6%），流程以串行为主，需检查步骤间的依赖关系是否正确

## 代表性流程

**流程 1**：定时关区停服（13 节点）
```
获取关区IP → TNM2告警屏蔽 → 蓝鲸监控告警屏蔽 → 置维护状态位 → 踢人-停tconnd4gs → 检查服务正常 → 停KVK和普通gamesvr → 清理脚本 → 置维护状态位 → 拉起gamesvr → 拉起tconnd4gs → 屏蔽蓝鲸
```
> 特点：区服关闭的标准流程 — 双重告警屏蔽+状态管理+进程停启

**流程 2**：区服导航配置备份（9 节点）
```
文件备份 → 上传到对比平台 → 等待1分钟 → 执行比较 → 获取任务日志 → 获取差异结果 → 检查其他机器md5 → 上报bkm → 发送消息
```
> 特点：配置文件的备份+比对+监控上报

**流程 3**：修改服务器名及前缀（6 节点）
```
暂停 → 批量更新集群属性 → 生成新host.xml配置 → 备份替换 → 加载配置生效 → 结果检查
```
> 特点：CC 批量更新+配置生成的典型区服管理流程
