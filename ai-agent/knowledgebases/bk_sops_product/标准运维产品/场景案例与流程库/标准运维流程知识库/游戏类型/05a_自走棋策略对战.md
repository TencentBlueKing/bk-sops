## 关键检查点（Review 要点）

1. **BCS Helm 部署回滚能力**：helm-plugin1（74 次）是核心发布方式，需确认 Helm release 的回滚策略和 revision 管理
2. **并行小服操作一致性**：并行率 24.8% 最高，大量小服并行操作（40+ 节点），需确认每个小服的操作结果一致
3. **GCloud 区服状态同步**：五件套（flag/custom_attrs/hide_status）的更新顺序和一致性
4. **停机维护流程完整性**：停机维护（47 节点）需确认所有小服禁用→操作→启用的闭环
5. **Warden 服务更新安全性**：Warden 更新流程有定时窗口（2小时间隔），需确认窗口内的监控覆盖
6. **AI 自走棋（ai-jk）集成**：33 次使用，需确认 AI 插件的超时处理和异常回退

## 代表性流程

**流程 1**：停机维护开始（47 节点）
```
[并行] 小服禁用×12 → 发送通知 → [并行] 小服禁用×12 → ...
```
> 特点：大量并行的小服禁用操作，单流程可达 47 节点

**流程 2**：BCS 扩容灰度（24 节点）
```
[分批] 10002-10003-20002-20003 → 开发确认 → 10006-10007-20006-20007 → 开发确认 → ... → 30001 → 正式服bcs小区更新？
```
> 特点：分批扩容+每批开发确认的谨慎灰度策略

**流程 3**：Warden 更新（11 节点）
```
确认正式服发布 → WardenMS下线+校验 → 定时2小时 → WardenMS发布+校验 → 定时2小时 → 下线+校验 → 发布+校验 → 定时2小时×4
```
> 特点：核心服务的滚动更新，每批间有 2 小时观察窗口
