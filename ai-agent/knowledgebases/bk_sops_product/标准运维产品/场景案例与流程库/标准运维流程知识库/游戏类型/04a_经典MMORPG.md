# 经典 MMORPG

> 经典 MMORPG 以分区分服架构为核心，涵盖传统端游改手游、回合/即时制 MMO、韩系/日系引进 RPG 等。运维流程特点是停服更新为主流发布模式、合服/开区/开服等区服生命周期管理高频、GCS 工单+DBM 数据库操作深度集成、流程复杂度跨度最大。
>
> **8,645** 条流程（含未分类 313 条）| **63** 个业务 | 平均节点数 8.5 | 中位节点数 4

## 关键检查点（Review 要点）

1. **停服更新完整性**：经典 MMORPG 停服更新（12.1%）是最核心场景。标准链路：告警屏蔽→踢人/关入口→停服→备份→版本更新→起服→健康检查→通知→解除屏蔽
2. **合服数据一致性**：合服（5.5%）需确保 GCS 工单→Spider 数据迁移→配置更新→区服状态变更的原子性
3. **GCS 工单闭环**：gcs_bill_execute 995 次，需确认工单状态检查和失败回滚
4. **DBM 操作审批链**：DBM 三件套（SQL执行→确认→轮询）需确保审批→执行→确认的完整链路
5. **GCloud 区服管理一致性**：预发布→发布→区服状态更新需跨 QQ/WX/iOS 各渠道一致
6. **告警屏蔽闭环**：TNM2（607 次）告警屏蔽后必须有对应的解除，避免遗漏
7. **多海外版一致性**：部分游戏有韩/越/欧美多海外版本，需确认各版本流程一致性

## 代表性流程

**流程 1**：灰度停服发布（53 节点）
```
告警屏蔽 → 修改TCM屏蔽外网+开GM → 停服(分批) → 清共享内存 → 版本包更新 → 代码更新 → 启动进程(分组) → 刷新bus管道 → BKChat通知测试验证 → 解除屏蔽
```
> 特点：经典的停服发布全流程模板，涵盖告警屏蔽/TCM/进程管理/bus刷新

**流程 2**：预发布停服更新（10 节点）
```
告警屏蔽 → 检查版本包md5 → FTP分发 → 停止进程 → 解压版本包 → 启动进程(gs/gw/sc) → 再次屏蔽 → 解除屏蔽
```
> 特点：开发商自助的标准停服更新，相对精简

**流程 3**：停服更新（96 节点）
```
大区预发布(多渠道) → 入口变亮 → 刷配置 → 发布单个渠道 → 服务端版本号修改 → TCM更新 → 停全局IDC进程 → 通知 → ...
```
> 特点：GCloud 区服管理+TCM 配置+多渠道发布的超大流程
