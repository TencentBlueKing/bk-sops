> 动作格斗 RPG 包括 DNF 系列等横版/3D 动作游戏。运维特点是 TCM 配置管理密度全 MMORPG 子类最高、客户端版本管理（做包/资源上传）是独特需求、蓝盾流水线联动深度、以及开区流程完整度高。
>

## 关键检查点（Review 要点）

1. **客户端做包完整性**：DNF 的做包流程（更新文件→MD5 上报→资源整理→GCloud 上传→手动确认→版本号写入）需确保每步的数据一致性
2. **TCM 配置变更安全性**：TCM 密度 0.92/流程全 MMORPG 最高，需确认配置变更的灰度验证和回滚能力
3. **双重告警屏蔽一致性**：同时使用 TNM2 + 蓝鲸监控屏蔽，需确保两者的屏蔽和解除时机一致
4. **蓝盾流水线联动**：devops-pl-plugin 139 次，需检查流水线调用的超时处理和失败回滚
5. **开区初始化完整性**：开区流程（检查GCS权限→业务初始化→DBM权限→配置生成→reload）需确保每步有前置检查
6. **副玩法 DB 变更审批**：DNF 的 GM 添加/副玩法配置通过 DBM 执行，需确认审批链路完整

## 代表性流程

**流程 1**：客户端做包（9 节点）
```
磁盘空间检查 → 重载获取版本号 → 更新文件上传 → MD5上报 → 客户端更新文件整理 → 版本号写入 → GCloud资源包上传 → 手动处理GCloud资源包 → 历史版本号写入
```
> 特点：客户端资源包的完整构建+上传流程

**流程 2**：开区新增小区（19 节点）
```
检查GCS权限 → 业务初始化(iJobs) → DBM权限申请 → 现网文件打包 → 生成新区配置 → 刷到现网 → reload配置 → 人工确认 → 设置维护状态 → 人工确认 → 生成对外配置 → 起小区进程
```
> 特点：完整的开区初始化流程

**流程 3**：副玩法服务端更新（15 节点）
```
停GameServer → 停周边模块 → 清理旧文件 → 周边+game文件整理 → 周边更新列表上传 → game文件分发 → 周边文件分发 → game模块更新 → 周边模块更新 → 起GameServer → 起周边模块 → BD变更
```
> 特点：分模块停启+文件分发的标准更新模式
