# 版本发布与更新

> 游戏运维最核心的流程类别。覆盖停服更新、不停服热更、全量发布等模式。流程复杂度最高（平均 12.5 节点），涉及文件分发、进程管理、配置同步、告警管理等多个环节。
>
> **5587** 条流程 | 平均节点数基于采样分析

---

## 关键检查点

1. 发布操作前后必须有告警屏蔽/取消屏蔽闭环（当前采用率 9%）
2. 版本更新前必须执行数据备份（当前采用率 6%）
3. 关键发布步骤前必须有人工确认节点（当前采用率 20%）
4. 停服后必须清共享内存再启服（当前采用率 2%）
5. 停服前关闭外网入口，开服后恢复（当前采用率 0%）
6. 版本文件分发后必须做 MD5 校验（当前采用率 14%）
7. 发布开始时必须发送通知（当前采用率 15%）
8. 发布完成后必须发送通知（当前采用率 38%）
9. 服务启动后必须执行健康检查（当前采用率 6%）
10. TCLS 中转服操作必须有加锁 → 操作 → 解锁（当前采用率 1%）
11. 停服操作需定时器控制执行时间点（当前采用率 17%）
12. 多区/多服操作使用并行网关提升效率（当前采用率 16%）
13. 涉及进程重启的发布流程，必须结合 CLB 进行无损发布（先摘流量 → 重启 → 健康检查 → 恢复流量）
14. 多渠道发布必须先发布手Q（SQ）渠道并验证无问题后，再发布微信（WX）渠道

## 通用模式

### 常见标准子流程

**1. 停服发布标准序列**
```
通知 → 定时等待（到停服时间） → 关闭入口/变灰 → 告警屏蔽 → 停止进程 → 清共享内存 → 版本更新 → 启动进程 → 健康检查 → 开放入口 → 取消告警屏蔽 → 通知
```

**2. TCLS 中转服发布序列**
```
TCLS锁定中转服 → TCLS发布至外网 → TCLS解锁中转服
```

**3. 告警屏蔽**
```
告警屏蔽（TNM2 + 蓝鲸监控） → 执行变更操作 → 取消告警屏蔽（TNM2 + 蓝鲸监控）
```

**4. DB 变更序列**
```
备份 → DB提单（并行多库） → [汇聚] → 人工确认SQL → 执行DB变更
```

**5. 版本分发与校验序列**
```
文件分发（服务端包） → MD5校验 → 人工确认 → 部署新版本
```

**6. 大区入口管理序列**
```
关闭入口/变灰 → 发布至外网 → 人工确认 → 开放入口/变亮
```

**7. 客户端+服务端并行准备**
```
[并行] → 服务端版本准备 | 客户端版本准备 | DB提单 | 告警屏蔽 → [汇聚] → 开始发布
```
