# 灰度发布

> 版本发布的重要子类型。按批次/分区逐步推进更新，降低发布风险。平均节点数最高（13.7），是最复杂的流程类别。
>
> **915** 条流程 | 平均节点数基于采样分析

---

## 关键检查点

1. 灰度操作前后必须有告警屏蔽/取消屏蔽闭环（当前采用率 6%）
2. 每个灰度批次后必须有人工确认节点验证效果（当前采用率 23%）
3. 多批次灰度之间必须有暂停等待验证（当前采用率 14%）
4. 灰度版本分发后必须做文件校验（当前采用率 9%）
5. 灰度区入口变灰 → 操作 → 入口变亮（当前采用率 1%）
6. 灰度发布开始时发送通知（当前采用率 20%）
7. 灰度批次启动后必须执行健康检查（当前采用率 6%）
8. 通过 CLB 权重控制灰度流量比例（当前采用率 7%）
9. 灰度更新前备份当前版本（当前采用率 3%）
10. 定时器控制灰度执行时间窗口（当前采用率 16%）
11. 多渠道发布必须先发布手Q（SQ）渠道并验证无问题后，再发布微信（WX）渠道

## 通用模式

### 常见标准子流程

**1. 灰度发布标准序列**
```
通知 → 告警屏蔽 → 关闭灰度区入口/变灰 → 定时等待（到发布时间） → 版本更新（灰度批次） → 人工确认 → 开放灰度区入口/变亮 → 取消告警屏蔽 → 通知
```

**2. CLB 灰度切流序列**
```
CLB查询RS列表 → CLB修改权重（灰度比例） → 通知 → 人工确认（验证灰度效果） → CLB恢复全量权重
```

**3. 分批灰度推进序列**
```
灰度第一台 → 人工确认 → 灰度前半部分 → 人工确认 → 灰度后半部分 → 人工确认 → 全量
```

**4. 灰度回退序列**
```
CLB摘灰度机流量 → 回退灰度版本 → CLB恢复灰度机流量 → 验证
```

**5. 灰度区入口管理**
```
入口变灰 → 通知 → 定时等待 → 执行灰度操作 → 通知 → 入口变亮
```
