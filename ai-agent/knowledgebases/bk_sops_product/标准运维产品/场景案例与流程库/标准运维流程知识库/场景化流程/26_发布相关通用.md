## 关键检查点

1. 发布期间必须有告警屏蔽/取消屏蔽闭环（当前采用率 5%）
2. 发布操作前必须有人工确认（当前采用率 21%）
3. 发布前必须执行备份（当前采用率 5%）
4. 发布开始时发送通知（当前采用率 17%）
5. 发布完成后发送通知（当前采用率 28%）
6. 发布后必须执行健康检查（当前采用率 4%）
7. 版本文件必须做 MD5 校验（当前采用率 10%）
8. 涉及进程重启的发布流程，必须结合 CLB 进行无损发布（先摘流量 → 重启 → 健康检查 → 恢复流量）
9. 多渠道发布必须先发布手Q（SQ）渠道并验证无问题后，再发布微信（WX）渠道

## 通用模式

### 常见标准子流程

**1. 通用发布序列**
```
通知 → 告警屏蔽 → 备份 → 版本更新 → 健康检查 → 取消告警屏蔽 → 通知
```

**2. TCM 配置发布序列**
```
TCM检查配置 → TCM禁用 → TCM安装 → TCM启用 → 人工确认
```

**3. 文件分发+校验序列**
```
文件分发 → MD5校验 → 通知 → 人工确认
```

**4. 定时发布序列**
```
通知 → 定时等待（到发布窗口） → 执行发布 → 通知 → 人工确认
```

## 检查清单

| 检查项 | 说明 | 严重程度 |
|--------|------|--------|
| 🔴 告警屏蔽 | 发布期间是否屏蔽告警 | 高 |
| 🔴 CLB 无损发布 | 涉及进程重启时是否结合 CLB 摘流量 → 重启 → 健康检查 → 恢复流量 | 高 |
| 🔴 渠道发布顺序 | 多渠道发布是否先发布手Q验证无问题后再发布微信 | 高 |
| 🟡 健康检查 | 发布后是否有健康检查 | 中 |
| 🟢 通知机制 | 发布完成是否有通知 | 低 |
| 🟢 版本记录 | 是否有版本信息记录 | 低 |
