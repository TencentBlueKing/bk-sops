# 平台与工具

> 平台与工具类指非游戏业务的基础设施和运维平台，包括蓝鲸、蓝盾等。运维流程特点是排他网关使用率最高（24.7%）、HTTP API 驱动（bk_http_request 全归属最高）、审批流程最完善、流程偏轻量化。
>
> **4,355** 条流程 | **88** 个业务 | 平均节点数 4.9 | 中位节点数 3

## 关键检查点（Review 要点）

1. **HTTP API 调用容错**：bk_http_request 3,945 次（0.91/流程），需检查超时设置、重试机制、错误码处理
2. **审批流程合规性**：bk_approve 305 次 + bksops-itsm 88 次，核心变更必须经过审批
3. **跨业务操作权限**：all_biz_job_fast_execute_script 423 次，需验证跨业务操作的权限范围
4. **条件分支完整性**：排他网关率 24.7%，每个条件分支都必须有处理逻辑（包括 else/default 分支）
5. **故障自愈闭环**：故障自愈（316 条流程），需检查故障检测→自动修复→验证→通知的完整链路
6. **混沌工程安全**：chaos-atom 45 次，故障注入实验需要有安全边界和回滚能力
7. **数据查询效率**：bkbase-query 44 次，大数据查询需要关注超时和资源消耗

## 代表性流程

**流程 1**：自动化测试报告输出（17 节点）
```
开始 → 变量预处理 → 获取业务字段 → 控制台数据获取 → 集群pod状态 → 集群版本状态 → 获取服务成功率 → 扁鹊可用性检查 → dsc自动探测 → 判断分支 → 结果数据上报 → 分发报告 → BkChat通知 → 检查域名 → 00-异常结果输出 → 结束
```
> 特点：多维度自动化检查 + 条件分支 + 报告生成

**流程 2**：指定进程重启（9 节点）
```
开始 → 审批人格式化 → 审批 → 生成进程数量 → 生成日志文件名 → 进程拉起 → 日志重定向检测 → 进程拉起(二次) → 发送消息 → 结束
```
> 特点：审批前置 + 日志检测的规范重启流程

**流程 3**：Helm 包版本发布（5 节点）
```
开始 → 环境初始化 → 拉取Helm包 → 生成diff文件 → 蓝鲸审批 → 更新文件 → 结束
```
> 特点：Helm + 审批的标准化容器发布模式
