# 海外业务

> 海外业务指面向海外市场运营的游戏版本，包括越南版、西方版、国际版等。运维流程特点是流程最简化（平均 1.9 节点）、工具链最轻量（以基础脚本执行为主）、尚处于运维标准化早期阶段。
>
> **199** 条流程 | **6** 个业务 | 平均节点数 1.9 | 中位节点数 1

## 关键检查点（Review 要点）

1. **基础运维规范**：海外流程极简化，Review 重点是检查是否缺少关键步骤（告警屏蔽、备份、通知、健康检查等）
2. **故障机管理**：cmdb_transfer_fault_host + cc_transfer_to_idle 使用相对频繁，需确认故障机转移后的资源回收流程
3. **发布流程完整性**：发布占 13.6% 但流程极简，需建议补充告警屏蔽、健康检查等步骤
4. **多地域网络考虑**：海外部署需要考虑跨地域网络延迟对脚本执行的影响
5. **合规要求**：不同地区可能有数据合规要求（如 GDPR），流程中需体现
6. **监控覆盖不足**：海外流程几乎没有告警屏蔽/监控相关操作，需建议补充
7. **通知机制**：海外团队可能使用不同的通知渠道，需确认通知覆盖

## 代表性流程

**流程 1**：server build deployment（9 节点）
```
开始 → build_download → configs_setup → td2cn_db_present → svc_shutdown → td2cn_db_update → services_launch → UserLogs_switch → wait 60s → result verify → 结束
```
> 特点：英文命名、标准的下载→配置→停服→DB更新→启动→验证流程

**流程 2**：BKCHAT 通知（6 节点）
```
开始 → BkChat通知 → 发送消息 → itsm审核群机器人通知 → 蓝鲸审批 → 发送通知 → bkchat通用消息通知 → 结束
```
> 特点：多渠道通知组合

**流程 3**：一个发布的案例（11 节点）
```
开始 → 定时 → 快速分发文件 → 定时 → 停周边 → 停游戏进程 → 更新 → 更新 → 快速执行脚本 → 消息展示 → 发送成功/失败通知 → 结束
```
> 特点：基础但完整的发布流程示例

## 改进建议

海外业务流程整体处于早期阶段，建议参考自研/发行业务的成熟实践逐步完善：

1. **补充告警屏蔽**：发布/重启流程前后应增加告警屏蔽/取消
2. **增加健康检查**：启动后应有进程/端口检查
3. **标准化通知**：关键操作前后应有通知
4. **引入备份机制**：版本更新前应有数据备份
5. **模板化管理**：将常用操作抽象为标准模板，减少单步流程
