## 关键检查点（Review 要点）

1. **TCM 配置变更原子性**：自研业务 TCM 密度 0.81/流程，需严格检查 TCM 变更的原子性和回滚能力
2. **蓝盾流水线联动**：devops-pl-plugin 533 次，CI/CD 与 SoPS 的联动需确保状态同步
3. **BKChat 通知完整性**：BKChat 使用 1,721 次（send+sops），需检查关键节点前后的通知覆盖
4. **ITSM 审批合规**：bksops-itsm 209 次，核心变更必须经过 ITSM 审批
5. **告警屏蔽闭环**：TNM2（946 次）+ 蓝鲸监控双重屏蔽，需确保取消屏蔽操作不遗漏
6. **灰度策略完整性**：3.5% 流程涉及灰度，自研业务灰度应覆盖灰度→验证→全量的完整链路
7. **预发布验证**：5.3% 涉及预发布，预发布环境配置需与正式环境保持一致

## 代表性流程

**流程 1**：停服灰度发布（53 节点）
```
开始 → 修改TCM屏蔽外网 → 停服 → 清共享内存 → 更新版本包 → 刷新bus → 启动进程 → BkChat通知测试 → 修改TCM解除屏蔽 → ... → 结束
```
> 特点：TCM + BKChat + 多服务器类型的自研标准发布模式

**流程 2**：测试服重启_bkchat（5 节点）
```
开始 → BK消息通知 → 停服 → 起服 → 检查ccs启动状态 → 检查启动状态-失败联系开发 → 结束
```
> 特点：轻量级重启 + BKChat 通知 + 启动验证

**流程 3**：预发布停服更新（10 节点）
```
开始 → FTP分发版本文件 → 检查md5 → 告警屏蔽 → 停止进程 → 解压版本包 → 启动进程 → 屏蔽解除 → 再次屏蔽防误告 → 结束
```
> 特点：完整的告警屏蔽闭环 + MD5 校验
