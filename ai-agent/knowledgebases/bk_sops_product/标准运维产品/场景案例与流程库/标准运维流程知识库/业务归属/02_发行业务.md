# 发行业务

> 发行业务指由外部开发商研发、腾讯负责发行和运营的游戏。运维流程特点是 GCS 工单系统驱动数据库变更、合服/开区场景高频、GCloud 区服管理深度使用、需要兼顾开发商协作边界。
>
> **6,189** 条流程 | **43** 个业务 | 平均节点数 7.3 | 中位节点数 3

## 关键检查点（Review 要点）

1. **GCS 工单闭环**：gcs_bill_execute（787 次）+ gcs_sqlserver_alter_bill（520 次），必须检查工单提交→状态轮询→结果验证→异常处理的完整链路
2. **合服数据完整性**：合服占 4.8%（发行最高频场景之一），需检查数据迁移、区服配置更新、GCloud 区服导航更新的完整性
3. **开发商操作边界**：发行业务流程中经常需要开发商确认（pause_node 密度 0.86/流程），需明确哪些步骤由运维执行、哪些由开发商确认
4. **GCloud 区服管理一致性**：GCloud 预发布→发布→区服状态更新的完整闭环
5. **SQL Server 变更安全**：gcs_sqlserver_alter_bill 520 次，SQL 变更需要有备份和回滚计划
6. **停服更新完整性**：停服占 13.7%（最高），完整的停服发布闭环尤为重要
7. **TCompose 执行状态**：tcompose-exec 276 次，需检查 TCompose 任务的状态轮询和异常处理
8. **DBM 三件套闭环**：confirm（263）+ poll（133）+ sqlexecute（103），DB 操作必须经过确认→执行→轮询的完整流程

## 代表性流程

**流程 1**：模块发布更新（29 节点）
```
开始 → 发消息-开始更新 → CLB服务更新 → 清共享内存 → 解压程序 → 推送配置 → reload配置 → reload数据档 → 逐批热更-migrate → 发消息-确认 → 服务更新写入历史 → 发消息-完成 → 结束
```
> 特点：CLB + 逐批热更 + 操作历史记录的发行标准模式

**流程 2**：区服导航管理（16 节点）
```
开始 → 人工确认 → 本地文本上传 → AQQ/AWX/IQQ/IWX 批量创建GCloud区服 → [并行] → 预发布大区 → 发布大区 → 人工确认 → 输出gcloud参数 → 结束
```
> 特点：多渠道（安卓QQ/微信 + iOS QQ/微信）GCloud 区服批量管理

**流程 3**：区服导航配置文件备份（9 节点）
```
开始 → 文件备份 → 上传到对比平台 → 执行比较 → 等待1分钟 → 获取差异结果 → 检查其他机器md5 → 获取任务日志 → 上报bkm → 发送消息 → 结束
```
> 特点：配置文件备份 + 差异比较 + 监控上报的发行标准备份模式
