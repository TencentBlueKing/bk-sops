## 问题描述

用户咨询蓝鲸标准运维**周期任务的并发执行**问题：

> 周期任务在上一个还没执行完的情况下，到了下一个触发时间点，是否会创建并执行新的任务？还是会等上一个结束后再执行？

## 解决方法

**结论：会触发。** 标准运维默认不做并发控制，到点就会创建并启动新的任务实例。

**原理说明：**

标准运维的周期任务基于 Celery Beat 调度实现，每次到达 Cron 表达式设定的时间点时，系统会：

- 创建一个新的 TaskFlowInstance（任务实例）
- 立即启动该实例执行
- **不会检查**上一次触发的任务实例是否已执行完毕

因此：上一个任务还在执行中时，到点后新任务会照常创建并执行，两个任务实例会**并行运行、互不干扰**。

**如何避免并发执行（推荐方案）：**

1. **合理设置 Cron 间隔**：确保任务执行时长远小于触发间隔，从根本上避免并发
2. **在流程中加入互斥逻辑**：在流程开始节点加入"检查是否有运行中任务"的步骤（如通过 HTTP 请求插件调用标准运维 API `get_task_list` 检查状态），若有则提前结束
3. **利用外部锁机制**：在流程中通过脚本节点（如作业平台执行脚本）操作 Redis/文件锁，实现互斥控制

**补充说明：**

上云版标准运维有以下限制：

- 单个项目最多创建 **50 个**周期任务
- 创建定时任务的间隔不能小于 **10 分钟**（防止过多高频任务影响调度性能）
- 如需放开此限制，需联系标准运维开发团队评估
