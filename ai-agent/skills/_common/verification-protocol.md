# 操作验证协议

> 本模块为 SOPS Skill 公共依赖，在打包时内联到各 Skill 的 SKILL.md 中。所有写操作必须在执行后进行结果验证。

---

## 1. 核心原则

**所有写操作**必须在执行后验证结果。验证的目的是确认操作**实际产生了预期结果**，而非仅依赖 API 调用的返回码。读操作无需验证。

| 操作类型 | 是否需验证 | 说明 |
|---------|-----------|------|
| 读操作 | 否 | 查询、获取信息等操作直接使用返回数据 |
| 写操作 | 是 | 创建、启动、重试、暂停、撤销等操作必须验证结果 |

---

## 2. 验证分类

| 类型 | 含义 | 时机 |
|------|------|------|
| 操作验证 | 写操作后确认结果符合预期 | 写操作 API 返回后立即执行 |
| 数据验证 | 分析结论的数据自检 | 输出报告/结论前 |
| 状态验证 | 异步操作的状态确认 | 写操作后延迟 poll |

---

## 3. 验证规则表

| Skill | 操作 | 验证方法 | 成功标准 |
|-------|------|---------|---------|
| task-runner | `create_task` | 检查返回的 task_id 和 task_url | task_id > 0 且 task_url 非空 |
| task-runner | `start_task` | 调用 `get_task_status` | 状态为 RUNNING 或 FINISHED |
| task-monitor | `operate_node`(retry) | poll `get_task_status` | 目标节点状态变为 RUNNING |
| task-monitor | `operate_task`(pause/revoke) | 调用 `get_task_status` | 任务状态符合预期操作（SUSPENDED/REVOKED） |
| troubleshooter | 建议修复并执行 | 重试失败节点后 poll 状态 | 节点通过或产生新的不同错误 |
| audit-reporter | 分页数据收集 | 对比 total_count 与实际收集条数 | 收集记录数 = API 报告的 total_count |
| ops-insight | 统计计算 | 关键指标交叉验证 | 各分类任务数之和 = 总任务数 |
| health-checker | 巡检发现 | 随机 spot-check 原始数据 | 抽取 1-2 个发现项，获取原始数据验证一致 |
| change-validator | 风险等级计算 | 规则表机械匹配 | 每个风险因子都命中规则表中的某一级 |
| flow-review | 成熟度评级 | checklist 逐项核对 | 每个检查项有明确的通过/不通过判定 |

---

## 4. 验证失败处理

| 失败类型 | 示例 | 处理方式 |
|---------|------|---------|
| 瞬时错误 | 网络超时、API 临时不可用 | 自动重试 1 次，仍失败则告知用户 |
| 业务错误 | 状态不符合预期、数据不一致 | 告知用户验证结果和差异，建议下一步操作 |
| 未知错误 | 验证方法本身执行异常 | 告知用户"无法确认操作结果"，建议手动检查 |

---

## 5. 与操作确认协议的关系

| 协议 | 阶段 | 目的 |
|------|------|------|
| 确认协议（confirmation-protocol） | 执行**前** | 确保操作意图正确 |
| 验证协议（verification-protocol） | 执行**后** | 确保操作结果正确 |

**写操作的完整流程**：

```
展示操作摘要 → 用户确认 → 执行操作 → 验证结果 → 反馈用户
  (确认协议)                        (验证协议)
```

**读操作**：无需确认，无需验证，直接执行并返回结果。
