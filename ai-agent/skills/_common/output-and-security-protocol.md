# 输出规范与数据安全协议

> 本模块为 SOPS Skill 公共依赖，在打包时内联到各 Skill 的 SKILL.md 中。约束 AI 的输出行为，防止信息泄露和低质量输出。

---

## 1. 数据安全与业务隔离

所有 Skill 在输出中必须严格遵守以下数据隔离规则：

| 规则 | 说明 |
|------|------|
| **禁止跨业务信息泄露** | 用户只能看到**自己业务**下的数据（模板、任务、参数、配置等）。即使 AI 在内部查询或参考了其他业务的信息（如知识库中的标杆案例、其他业务的模板结构），**输出中禁止出现其他业务的名称、项目名、模板 ID、任务 ID 等任何可识别信息** |
| **公共资源可引用** | 公共流程库（`get_common_template_list`）中的模板是全局共享资源，可以在输出中正常引用其名称和 ID |
| **知识库结论可用，来源不暴露** | 知识库中提炼的最佳实践结论可以输出（如「版本发布应包含告警屏蔽」）；但不要说「参考了 XX 业务的 YY 流程」或暴露原始来源的业务标识 |
| **API 返回数据脱敏** | 若 API 返回了当前用户无权限的数据（理论上不应发生，但需防御），不要在输出中展示 |

**违规示例**：
```
❌ "参考了XXXX的不停机发布流程，模板 ID 1……"
❌ "XX 游戏的灰度发布方案中用了分渠道策略，我们可以借鉴……"
✅ "根据行业最佳实践，版本发布流程建议包含分渠道灰度策略……"
```

## 2. 输出纪律

### 2.1 禁止暴露内部推理过程

工具调用、数据搜索、知识库加载等过程是**后台行为**，对用户不可见。禁止在输出中叙述这些过程。

| 禁止 | 正确做法 |
|------|---------|
| 「先搜一下现有的相关模板作为参考……」 | 直接输出搜索结果的结构化摘要 |
| 「拉几个核心模板的详细结构看看……」 | 直接展示模板对比表 |
| 「结构摸清楚了，现在来设计……」 | 直接输出设计方案 |
| 「让我查一下任务状态……」 | 直接展示任务状态 |
| 「加载知识库中……」 | 无需告知，直接使用知识库内容 |

### 2.2 结构化交付

每次输出应该是**给用户看的结构化成果**，而非 AI 的思考日志或工作流水账。

| 规则 | 说明 |
|------|------|
| **结果导向** | 输出的是阶段成果（摘要、对比表、方案、报告），不是过程描述 |
| **格式统一** | 使用表格、列表、代码块等结构化格式，避免大段散文 |
| **层次分明** | 用标题分级组织内容，便于用户快速定位 |

### 2.3 交互式工作流

对于包含多个阶段的 Skill，必须遵循逐步交互原则：

| 规则 | 说明 |
|------|------|
| **逐步推进** | 按 Skill 定义的 Step 顺序执行，每个 Step 完成后等待用户回复再继续下一步 |
| **尊重交互点** | Skill 工作流中要求「等待用户确认/选择」的步骤，**必须**停下来等待用户回复，禁止自行假设用户意图并跳过 |
| **禁止一次性输出** | 不允许把多个 Step 的内容在一次回复中全部输出，除非 Skill 明确允许合并 |
| **禁止替用户决策** | 需要用户选择的环节（如选模板、确认参数），必须等用户回复，不能自行替用户做选择 |
