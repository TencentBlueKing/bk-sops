# 操作确认协议

> 本模块为 SOPS Skill 公共依赖，在打包时内联到各 Skill 的 SKILL.md 中。所有写操作必须遵循本协议。

---

## 1. 核心原则

**所有写操作**必须在执行前获得用户确认。读操作（查询、获取信息）无需确认，直接执行。

| 操作类型 | 示例 | 是否需确认 |
|---------|------|-----------|
| 读操作 | 查询任务状态、获取模板信息、获取日志 | 否 |
| 写操作 | 创建任务、启动任务、重试节点、跳过节点、暂停/撤销任务 | 是 |

---

## 2. 操作分级

| 风险等级 | 操作类型 | 确认方式 |
|---------|---------|---------|
| 🟢 低风险 | 查询任务状态、获取模板信息、获取日志 | 无需确认，直接执行 |
| 🟡 中风险 | 创建任务、启动任务、重试节点 | 展示操作摘要 → 用户确认 → 执行 |
| 🔴 高风险 | 跳过失败节点、暂停任务、撤销任务 | 展示操作摘要 + 风险提示 → 用户明确确认 → 执行 |

---

## 3. 确认摘要格式

在执行任何写操作前，必须展示以下格式的摘要：

```
即将执行的操作：
- 操作类型：{创建任务 / 启动任务 / 重试节点 / ...}
- 目标：{流程名称} / {任务 ID} / {节点名称}
- 关键参数：{参数列表}
- 影响范围：{涉及的业务/主机/服务}
```

**示例（创建并启动任务）**：
```
即将执行的操作：
- 操作类型：创建任务并启动
- 目标：流程「服务发布-灰度更新」
- 关键参数：version=2.1.0, env=prod, hosts=10.0.1.1,10.0.1.2
- 影响范围：业务「游戏中心」，生产环境 2 台主机
```

**示例（高风险操作）**：
```
即将执行的操作：
- 操作类型：跳过失败节点
- 目标：任务 #12345，节点「健康检查」
- 关键参数：无
- 影响范围：跳过后流程将继续执行后续节点，可能导致未经验证的状态进入生产

⚠️ 风险提示：跳过节点将绕过该步骤的校验，请确认该操作符合预期。
```

---

## 4. 批量操作

- **原则**：多个写操作原则上需**逐项确认**
- **例外**：同类型批量操作（如：同一任务下重试多个失败节点）可**合并确认**，但必须列出每项操作的明细

**合并确认示例**：
```
即将执行的操作（批量重试，共 3 项）：
- 操作类型：重试节点
- 目标：任务 #12345
- 明细：
  1. 节点「部署服务」- 失败原因：超时
  2. 节点「配置更新」- 失败原因：连接拒绝
  3. 节点「健康检查」- 失败原因：端口未监听
- 影响范围：业务「游戏中心」，生产环境
```

---

## 5. 确认结果处理

| 用户反馈 | 处理方式 |
|---------|---------|
| 确认执行 | 执行操作，并反馈执行结果 |
| 请求修改 | 按用户要求调整后，重新展示摘要供再次确认 |
| 取消操作 | 不执行，明确告知用户已取消 |
