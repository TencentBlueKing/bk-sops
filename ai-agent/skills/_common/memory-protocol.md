# 记忆读写协议

> 本模块为 SOPS Skill 公共依赖，在打包时内联到各 Skill 的 SKILL.md 中。定义记忆存储结构、加载流程、沉淀触发点与写入规则，是 Skill 能够**学习与持续改进**的核心机制。

---

## 1. 记忆存储结构

每个 Skill 的 `memory/` 目录采用统一的双层结构：**业务维度**与**用户维度**。业务知识（流程、参数、问题、规则）与用户偏好（确认方式、通知偏好、操作习惯）分离存储，各自独立演进。

```
memory/
├── businesses/          # 业务维度知识
│   ├── _template.md     # 模板（新建业务记忆时复制）
│   └── {业务标识}.md    # 各业务的专属知识
└── users/               # 用户维度偏好
    ├── _template.md     # 模板（新建用户记忆时复制）
    └── {用户标识}.md    # 各用户的个人偏好
```

**标识约定**：
- **业务标识**：通常为蓝鲸业务 ID 或业务英文名，如 `2`、`game_center`
- **用户标识**：从环境变量、认证信息或对话中提取，需保证同一用户在不同会话中可被一致识别

## 2. 业务记忆模板 (businesses/_template.md)

新建业务记忆时，从以下模板复制并填充：

```markdown
# {业务名称}

## 基础信息
- 业务 ID：
- 常用项目空间 ID：
- 环境信息：（prod/stage/自定义）

## 常用流程
| 流程名称 | 模板 ID | 用途 | 典型参数 |
|---------|---------|------|---------|

## 参数偏好
（该业务常用的默认参数值，如部署路径、服务名、通知群等）

## 已知问题
（该业务历史上遇到过的问题和解决方案。状态按 feedback-protocol §3 问题生命周期管理：已发现/待修复/修复中/已验证/已关闭/已忽略）

| 问题 | 状态 | 发现时间 | 最后更新 | 解决方案 |
|------|------|---------|---------|---------|

## 业务特殊规则
（如该业务的变更窗口期、审批要求、特殊操作流程等）

## 约束规则
（业务特定的规则覆盖，优先级高于 skill 内置默认值。格式与各 skill 内置规则表一致，此处配置的值会覆盖默认值）

### 变更风控
| 风险因子 | 低风险 | 中风险 | 高风险 |
|---------|--------|--------|--------|

### 健康基线
| 检查项 | 正常 | 警告 | 严重 |
|--------|------|------|------|

### 审计异常阈值
| 异常类型 | 触发条件 |
|---------|---------|

## 执行足迹

| 时间 | 流程模板 | 操作类型 | 结果 | 关键参数 | 备注 |
|------|---------|---------|------|---------|------|
```

## 3. 用户记忆模板 (users/_template.md)

```markdown
# {用户标识}

## 角色信息

- 确认方式偏好：（详细确认 / 简洁确认）

- 报告格式偏好：（详细 / 精简）

## 常用操作
| 操作 | 频率 | 备注 |
|------|------|------|

## 个人笔记
（用户主动记录的备忘信息）
```

## 4. 记忆加载流程

**每次 Skill 启动时**执行以下 5 步，将业务与用户记忆作为上下文引入：

| 步骤 | 动作 | 说明 |
|------|------|------|
| 1 | 识别当前用户 | 从环境变量、认证信息或对话上下文中获取用户标识 |
| 2 | 识别当前业务 | 从用户提供的参数（如业务 ID、项目 ID）或对话上下文中获取业务标识 |
| 3 | 加载用户记忆 | 检查 `memory/users/{用户标识}.md` 是否存在 → 存在则读取**章节标题**（## 级别），得到"记忆目录" |
| 4 | 加载业务记忆 | 检查 `memory/businesses/{业务标识}.md` 是否存在 → 存在则读取**章节标题**（## 级别），得到"记忆目录" |
| 5 | 容错与引导 | 记忆文件不存在**不影响功能**，在合适时机引导用户创建记忆 |

**加载后的使用**：
- 启动时加载的"记忆目录"仅包含章节标题，用于快速判断哪些信息可用
- 在后续工作流程的具体步骤中，根据需要读取对应章节的**完整内容**（按需深入）
- 各 Skill 在自身的「上下文需求清单」中定义每个步骤需要的记忆章节和加载时机
- 若用户或业务无法识别，跳过对应维度的加载，仅依赖对话中的显式信息

### 4.1 按需深入

各 Skill 在工作流程中按需读取记忆章节的完整内容。以下为常见的按需加载映射：

| Skill 步骤 | 需要的记忆章节 | 加载时机 |
|-----------|--------------|---------|
| task-runner 定位流程 | `## 常用流程` | 用户没有指定模板 ID 时 |
| task-runner 填充参数 | `## 参数偏好` | 展示参数表前 |
| troubleshooter 匹配已知问题 | `## 已知问题` | 错误分类完成后 |
| change-validator 读取风控规则 | `## 约束规则 > 变更风控` | 计算风险等级前 |
| health-checker 读取基线 | `## 约束规则 > 健康基线` | 执行检查前 |
| audit-reporter 读取阈值 | `## 约束规则 > 审计异常阈值` | 标注异常前 |
| flow-review 读取业务检查规则 | `## 业务特殊规则` | 执行检查前 |

各 Skill 可在自身 SKILL.md 的「上下文需求清单」中定义更详细的按需加载规则。

## 5. 引导阶段模型

根据记忆的完整程度，采用不同的引导策略：

| 阶段 | 判断条件 | 引导策略 |
|------|---------|---------|
| **初识期** | 该用户/业务无记忆文件 | 主动但克制地引导建立基础记忆。每次只问 1-2 个最关键的信息，避免一次性采集过多导致反感 |
| **成长期** | 有记忆文件但信息不完整 | 在操作过程中自然地补充记忆。发现新信息时询问是否记录，不强求 |
| **成熟期** | 记忆信息充分 | 利用记忆提高效率（自动预填参数、主动推荐），偶尔确认记忆是否需要更新 |

**示例**：

- **初识期**：用户首次操作业务 →「这是你第一次在 {业务} 上操作，要不要记录一些基础信息方便下次使用？」
- **成长期**：用户填写非默认参数 →「你刚才填的 {参数}={值}，这个是该业务的常用值吗？要记住吗？」
- **成熟期**：直接预填 →「基于使用习惯已准备好参数，只需确认 version。」

## 6. 记忆沉淀触发点

### 6.1 主动询问触发

在以下时机**主动询问**用户是否记录：

| 时机 | 引导话术示例 |
|------|-------------|
| 首次操作某业务 | 「这是你第一次在 {业务} 上操作，要不要记录一些基础信息方便下次使用？」 |
| 用户填写了非默认参数 | 「你刚才填的 {参数}={值}，这个是该业务的常用值吗？要记住吗？」 |
| 用户遇到并解决了问题 | 「这个问题的解决方案要记录下来吗？下次遇到可以直接参考。」 |

### 6.2 自动提炼触发

操作完成后**自动提取**并**确认**是否记录：

| 时机 | 提炼内容 | 确认话术 |
|------|---------|---------|
| 任务成功执行后 | 使用的流程模板、关键参数 | 询问是否作为该业务的常用配置 |
| 问题排查完成后 | 问题现象 + 解决方案 | 询问是否加入业务已知问题库 |
| 重复操作检测 | 连续 2 次以上使用相同参数执行同一流程 | 主动建议记录为常用操作 |

## 7. 记忆写入规则

| 规则 | 说明 |
|------|------|
| **确认前置** | 所有记忆写入前**必须**向用户展示将要写入的内容并获得确认 |
| **追加方式** | 采用追加方式写入，**不覆盖**已有记忆。新增内容追加到对应章节末尾 |
| **用户主权** | 用户可以随时要求**查看**、**编辑**或**删除**已有记忆；Skill 需支持这些操作 |

---

## 8. 记忆过期与清理

| 策略 | 说明 |
|------|------|
| **无自动过期** | 记忆不设置自动过期时间，由用户主动管理 |
| **定期提示** | 在合适的交互时机提示：「你的 {业务} 记忆上次更新是 X 天前，要检查一下是否需要更新吗？」 |
| **随时管理** | 用户可随时查看、编辑、删除任何记忆，Skill 需响应用户的管理意图 |

## 9. 跨 Skill 记忆联动

记忆格式在各 Skill 间统一，便于未来打通共享。以下为设计层面的联动关系：

| 来源 Skill | 记忆内容 | 消费 Skill |
|-----------|---------|-----------|
| task-runner | 常用参数 | troubleshooter 排查参考 |
| troubleshooter | 已知问题库 | task-monitor 实时匹配 |
| change-validator | 变更规则 | task-runner 执行前校验 |
| health-checker | 巡检发现 | flow-reviewer 重点检查 |

**当前实现**：各 Skill 独立存储 memory，格式统一。后续若需跨 Skill 共享，可按需打通。

## 10. 约束规则优先级

Skill 内置的默认规则表和业务记忆中的约束规则采用**两层覆盖**机制：

| 层级 | 来源 | 优先级 | 说明 |
|------|------|--------|------|
| 默认规则 | 各 Skill 的 SKILL.md 内置 | 低 | 适用于所有业务的通用基线 |
| 业务规则 | 业务记忆 `## 约束规则` | 高 | 业务特定覆盖，缺失时回退到默认 |

使用规则时：先检查业务记忆中是否有对应的约束规则章节 → 有则使用业务值 → 无则使用 Skill 内置默认值。

---

## 11. 与操作确认协议的关系

- **记忆读取**：属于读操作，无需用户确认
- **记忆写入**：属于写操作，必须遵循本协议的「记忆写入规则」，即：展示内容 → 用户确认 → 执行写入
